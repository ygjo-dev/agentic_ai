### 여기 없는 것

**실제 데이터 내용**(노드 개수 · 특정 노드 이름 · menu 크기)은 단언하지 않는다.
요구사항이 바뀌면 함께 바뀌는 값이라, 테스트로 박아두면 데이터를 손볼 때마다
빨간불이 뜨고 그 빨간불은 아무것도 알려주지 않는다.

그쪽은 값이 필요한 작업에서 한 번 재서 `NOTES.md` 에 적는다.

**구현 세부**도 없다. 함수의 인자가 출력에 그대로 나타나는지, 한국어 조사를
어떻게 붙이는지 같은 것들이다. 명세로 읽으면 정보가 0이다.

## `demo/` — 배치 불변식만 남겼다 (63개)

`demo/` 는 시연용이고 실제 서비스는 소켓 · MCP 로 대체되므로 **통째로 사라질
계층**이다. 구조가 계속 바뀌는 중이라 그 테스트들은 회귀를 잡는 게 아니라
변경을 따라다니고 있었다 — 제품 코드는 한 번에 고쳐지는데 테스트만 네 번씩
실패–수정–재실행이 돌았고, 그 네 번이 전부 "요구사항이 바뀌어서" 였다.

그래서 장면 · 색 · 강조 · DOT 문법 · 응답 계약을 지키던 것들을 지웠다.
**189개 중 126개를 지우고 63개를 남겼다.** 남긴 기준은 하나다 —
**화면을 봐도 확인할 수 없는 것.**

```
로직 오염   "말이 안 되는 경로가 등록됐다"   화면을 보면 안다   -> 지웠다
배치 오염   "노드가 3pt 움직였다"            화면을 봐도 모른다 -> 남겼다
```

3pt 는 안 보이고 30pt 면 이미 시연이 깨진 뒤다. 사람의 눈을 대신하는 테스트는
버리고, 눈이 못 보는 것만 남긴다.

여기 있는 단언 대부분은 **몇 주에 걸쳐 실측으로 알아낸 배치 성질**이다.
어떤 강조 조합에서도 좌표가 같다 · 노드를 등록해도 기존 노드가 안 움직인다 ·
`inputscale=72` · 핀이 있으면 `overlap` 금지 · 회전은 최초 배치에만.
지우면 다시 알아낼 방법이 없으므로 함부로 손대지 않는다.

**`demo/` 테스트를 늘리지 않는다.** 화면이 깨지는 것은 화면을 띄워 본다.

## 저장소를 더럽히지 않는다

등록 테스트는 실제 YAML 파일을 쓴다. 전부 임시 디렉터리로 격리한다
(`conftest.isolated_workspace`). 리허설로 만들어둔 시연 상태가 `pytest` 한 번에
날아가면 시연 당일 사고가 된다.
