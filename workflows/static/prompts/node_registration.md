사람이 쓴 새 노드 정보를 보고 노드 id 와 properties 를 정한다.

[properties 가 하는 일]
- properties 는 인터페이스(inputs/outputs)로 표현되지 않는 성질을 적는 곳이다.
- 두 노드가 같은 key 와 같은 value 를 가지면 그 둘 사이에 점선이 그려진다.
  점선은 "같은 것을 다룬다" 는 뜻이다.
- 즉 properties 는 단순한 꼬리표가 아니라, 이 노드가 기존 노드와
  어떤 관계인지를 드러내는 수단이다.

[쓸 수 있는 property key]
{property_keys}

- 이 목록에 없는 key 는 절대 쓰지 마라. key 어휘가 갈라지면 조회가 실패한다.
- subject 는 "이 노드가 무엇을 다루는가" 다. 노드가 불러오기든 분석이든 생성이든
  상관없이 같은 대상을 다루면 같은 값을 쓴다.

[subject 에 지금 쓰이고 있는 값]
- 승강장
- 궤도
- 기상

**가장 중요한 규칙이다.** 새 노드가 위 대상 중 하나를 다루면 그 값을
**글자 그대로** 쓴다. 뜻이 같아도 다른 낱말을 쓰면 아무와도 이어지지 않는다.

- `궤도` 를 `선로` · `레일` · `트랙` 으로 바꿔 쓰지 마라.
- `기상` 을 `날씨` · `기후` · `환경` 으로 바꿔 쓰지 마라.
- `승강장` 을 `플랫폼` · `역사` 로 바꿔 쓰지 마라.

위 목록은 [기존 노드] 의 properties 에서 온 것이다. 둘이 어긋나 보이면
[기존 노드] 에 실제로 적힌 값을 따른다.

[관계가 없을 때]
- 어느 대상에도 매이지 않는 범용 노드(예: 형식만 바꾸는 생성 노드)는
  properties 를 빈 객체 {{}} 로 둔다.
- 억지로 새 값을 지어내지 마라. 아무와도 안 이어지는 값을 만드느니 비우는 편이 낫다.
  점선이 안 생길 뿐 등록은 정상이다.

[판단 순서]
1. 새 노드가 무엇을 다루는지 한 낱말로 정한다.
2. 그것이 [subject 에 지금 쓰이고 있는 값] 중 하나와 같은 대상인지 본다.
3. 같으면 그 값을 글자 그대로 쓴다. 아니면 비운다.

[노드 id 규칙]
- 소문자 영문과 언더스코어만 쓴다. 숫자와 대문자, 공백, 한글은 쓰지 않는다.
- 기존 id 와 같은 형식으로 짓는다.
  예: 불러오기는 load_, 분석은 analyze_ 또는 detect_ 또는 summarize_,
      생성은 generate_ 로 시작한다.
- 기존 노드의 id 와 겹치면 안 된다.
- 사람이 쓴 이름과 설명의 뜻이 드러나게 짓는다.

[출력]
- node_id : 위 규칙을 지킨 노드 id.
- properties : {{key: value}} 형태. 관계가 없으면 {{}}.
- reason : 어느 기존 노드와 왜 관계있다고 봤는지 짧게. 관계가 없다고
  판단했으면 그렇게 쓴다.
