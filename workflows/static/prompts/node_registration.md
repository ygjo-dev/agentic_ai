사람이 쓴 새 노드 정보를 보고 노드 id 와 properties 를 정한다.

[properties 가 하는 일]
- properties 는 인터페이스(inputs/outputs)로 표현되지 않는 성질을 적는 곳이다.
- 두 노드가 같은 key 와 같은 value 를 가지면 그 둘 사이에 점선이 그려진다.
  점선은 "같은 것을 다룬다" 는 뜻이다.
- 즉 properties 는 단순한 꼬리표가 아니라, 이 노드가 기존 노드와
  어떤 관계인지를 드러내는 수단이다.

[판단 순서]
1. 새 노드가 기존 노드 중 무엇과 관계있는지 먼저 본다.
2. 그 관계가 무엇을 공유하는지 정한다.
   같은 대상을 분석하는가? 같은 원천에서 데이터를 얻는가?
   같은 성격의 산출물을 만드는가?
3. 그것을 아래 어휘의 key: value 로 쓴다.
   관계된 기존 노드와 value 까지 똑같아야 점선이 생긴다.

[쓸 수 있는 property key]
{property_keys}

- 이 목록에 없는 key 는 절대 쓰지 마라. key 어휘가 갈라지면 조회가 실패한다.
- value 는 새로 지어도 된다. 다만 기존 노드와 관계를 드러내려면
  그 노드가 쓰는 value 와 글자까지 똑같이 써야 한다.
- 관계있는 기존 노드가 없으면 properties 를 빈 객체 {{}} 로 둔다.
  억지로 기존 key 에 끼워 맞추지 마라. 점선이 안 생길 뿐 등록은 정상이다.

[노드 id 규칙]
- 소문자 영문과 언더스코어만 쓴다. 숫자와 대문자, 공백, 한글은 쓰지 않는다.
- 기존 id 와 같은 형식으로 짓는다.
  예: 불러오기는 load_, 분석은 analyze_ 또는 detect_ 또는 summarize_,
      생성은 generate_ 로 시작한다.
- 기존 노드의 id 와 겹치면 안 된다.
- 사람이 쓴 이름과 설명의 뜻이 드러나게 짓는다.

[출력]
- node_id : 위 규칙을 지킨 노드 id.
- properties : {{key: value}} 형태. 관계가 없으면 {{}}.
- reason : 어느 기존 노드와 왜 관계있다고 봤는지 짧게. 관계가 없다고
  판단했으면 그렇게 쓴다.
